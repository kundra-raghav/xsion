## PROMPT 2 (Backend) — Implement fingerprint v1 utility (URL normalize + signature + hash)

**Prompt:**
Implement fingerprint v1 utilities for Xsion discovery.

Create `apps/api/src/utils/fingerprint.ts` with:

1. `normalizeUrl(rawUrl: string): string`

* Remove query string and hash.
* Normalize trailing slash.
* Replace obvious numeric IDs in path segments with `:id`:

  * any segment that is all digits -> `:id`
  * any segment that matches UUID v4 -> `:uuid`
  * any segment longer than 12 chars that is mostly hex -> `:token`
* Return normalized absolute URL if possible; if rawUrl is relative, leave as is.

2. `extractPageSignature(page): Promise<{ title?:string; h1?:string; navLabels:string[]; ctas:string[] }>`

* Input is a Playwright `Page`.
* Collect:

  * document.title()
  * first visible H1 text (fallback: first visible h2)
  * nav labels: visible text from up to 5 elements in nav (`nav a`, `nav button`)
  * ctas: visible text from up to 3 primary-ish buttons (visible buttons with longer text, exclude tiny icons)
* Trim, de-dupe, limit lengths.

3. `computeFingerprint(normalizedUrl: string, sig: {...}): string`

* Hash using sha256 of a stable JSON string of `{normalizedUrl,title,h1,navLabels,ctas}`
* Return hex string.

4. `getFingerprintForPage(page): Promise<{ normalizedUrl:string; fingerprint:string; title?:string; h1?:string }>`

* Uses page.url(), normalizeUrl, extractPageSignature, computeFingerprint.

Update `apps/api/src/runners/playwrightDiscovery.ts` to use this fingerprint function everywhere a “state identity” is needed.

Must compile. No new dependencies besides Node crypto.

Output only code changes.

## PROMPT 3 (Backend) — Candidate selection v1 + denylist + loop detection primitives

**Prompt:**
Implement candidate action selection v1 for Playwright exploration.

Create `apps/api/src/runners/candidates.ts` exporting:

* `type CandidateAction = { type:'click'; label?:string; selectorBundle: SelectorBundle; score:number; elementHint?: { tag?:string; role?:string } }`
* `type SelectorBundle = { preferred: { kind:'role'|'testid'|'text'|'css'; role?:string; name?:string; value?:string }; fallbacks: Array<...same shape...> }`

Implement `async getCandidateActions(page, opts): Promise<CandidateAction[]>`:

* Find clickable elements: `a[href]`, `button`, `[role=button]`
* Filter: visible, enabled
* Exclude dangerous by label match (case-insensitive) if label includes any of:
  delete, remove, cancel, pay, logout, unsubscribe, deactivate, destroy
* Exclude very small elements (bounding box w/h < 18px) unless inside nav.
* Extract label priority:

  * aria-label
  * innerText trimmed
  * title attribute
* Build selector bundle priority order:

  1. role+name (if role exists and label exists)
  2. data-testid (if present)
  3. text selector (exact-ish)
  4. css fallback (a stable-ish css with nth-of-type only as last resort)
* Score actions:

  * nav items higher
  * longer meaningful labels higher (3–30 chars)
  * penalize generic labels like “ok”, “yes”, “submit”, “click”
* Return top N candidates (default 12)

Also export:

* `isDangerousLabel(label?:string): boolean`
* `makeActionKey(fingerprint:string, candidate:CandidateAction): string` used for loop detection.

No external deps.

Output only code changes.

## PROMPT 4 (Backend) — Upgrade Playwright discovery loop (step events + budgets + loop stops)

**Prompt:**
Upgrade the real Playwright discovery runner to use step-level WS events, fingerprint v1, and candidate selection v1.

Modify `apps/api/src/runners/playwrightDiscovery.ts` (or wherever your real runner lives) to:

1. Use budgets:

* maxMinutes=8
* maxActions=120
* maxStates=30
* stopAfterNoNewStateSteps=10

2. Maintain:

* `seenStatesByFingerprint: Map<string, stateId>`
* `visitedActionKeys: Set<string>` where key is makeActionKey(currentFingerprint, candidate)
* `noNewStateCounter`

3. Each loop iteration:

* Get current state fingerprint via `getFingerprintForPage`

* Emit WS `step:start` with stepIndex, state url+fingerprint+title, candidatesCount

* Select best candidate not yet visited and not dangerous

* Emit `step:action` with selectorBundle + label

* Execute click using selectorBundle preferred then fallbacks:

  * Implement helper `clickWithSelectorBundle(page, bundle)` that tries role/testid/text/css in order.

* After click, wait strategy:

  * await page.waitForLoadState('domcontentloaded', timeout 10s) (ignore if timeout)
  * small stabilization wait 250ms

* Compute new fingerprint

* If new fingerprint not seen:

  * create StateNode in store (include normalizedUrl, fingerprint, title, optional h1)
  * add TransitionEdge in store
  * emit `graph:add` with the new node+edge
  * reset noNewStateCounter=0

* Else:

  * link edge to existing state, emit `graph:add` edge only
  * increment noNewStateCounter

* Emit `step:result` with fromFingerprint, toFingerprint, createdNewState, url

4. On any error:

* take screenshot artifact via artifacts helper, emit `step:error` with message and screenshot key
* increment noNewStateCounter

5. Emit progress events based on elapsed time and/or actions.
6. Update DiscoveryRun status appropriately and emit status/done.

Must not crash if no candidates available—end run gracefully.

Output only code changes.
